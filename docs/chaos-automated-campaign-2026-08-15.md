# 관리자 개입 최소화 자동 캠페인

## 실행 구조

| 구간 | 케이스 | 관리자 개입 |
|---|---:|---:|
| 안정 D810에서 소프트웨어 전체 조합 | 48 | 0 |
| D810 전원 재인가 직후 조합 | 16 | 첫 행에서 1회 |
| D810 USB 재연결 직후 조합 | 16 | 첫 행에서 1회 |
| 순서 의존 경쟁 | 12 | 0 |
| 합계 | 92 | 2회 |

소프트웨어 전체 조합은 ddserver 3상태, session manager 4상태, S10 4상태의 `3 × 4 × 4 = 48개`를 모두 포함한다. D810의 정상·대기 복귀와 운영 모드·로그·전송 조건은 유효 페어 186개를 100% 덮도록 배치한다.

전원 재인가와 USB 재연결은 각 행마다 반복하지 않는다. 각 물리 사건을 한 번 수행한 뒤 동일한 복구 epoch에서 16개 소프트웨어 페어 조합을 실행한다. 전체 캠페인의 실제 셔터 작동은 0회다.

## 자동 연결과 안전 정지

- 이 캠페인은 S10 Wi-Fi, Opal LAN/WAN, 인터넷 연결을 의도적으로 끊지 않는다. 기존 `wifi_reconnect` 행은 네트워크 연속성 확인으로만 실행한다.
- S10 ADB는 지정 포트, 이전 성공 포트, 현재 `adb devices`, mDNS 순서로 자동 탐색한다.
- S10 Wi-Fi 재연결은 기기에서 Wi-Fi를 8초간 내렸다가 자동 복귀시키고 ADB를 다시 탐색한다.
- D810 전원과 USB 물리 단계에서만 `WAITING`으로 멈춘다.
- 각 단계 뒤 원자적 `state.json`을 저장하고 미완료 단계부터 재개한다.
- Opal 여유 공간 5MB 미만에서는 비전송 단계를 시작하지 않는다.
- 최종 checkpoint 뒤 outbox를 다시 회수하며 동시 생성 잔여는 최대 2개만 허용한다.
