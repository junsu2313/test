# 출사형 실전 테스트 준비안

작성일: 2026-08-12

## 목표

Opal 내부 가상 클라이언트 반복 테스트가 아니라, 실제 출사에서의 사용자 흐름을 재현한다. S10은 실제 `com.example.underlab_camera` 앱을 실행하고, Opal은 카메라 서비스와 관측·백업을 담당한다.

## 실제 출사 흐름

```text
Opal 전원 및 STA/SSID 준비
        ↓
D810 전원·USB 연결
        ↓
S10 전원·SSID 연결·앱 실행
        ↓
앱에서 Ready 확인
        ↓
앱에서 라이브뷰 시작
        ↓
AF → 라이브뷰 프레임 확인 → UI 셔터
        ↓
단발·연사·촬영 프리뷰 확인
        ↓
앱을 유지한 채 Opal 서비스 재시작/복구 시나리오
        ↓
앱 자동 재연결 및 다시 촬영
```

## 준비 조건

- D810 배터리 완충 또는 외부 전원
- S10 화면 자동 꺼짐·Wi-Fi 절전 해제
- S10 앱 화면을 켠 상태로 유지
- Opal 저장공간 20MB 이상, outbox 수집기 실행
- PC는 Tailscale로 관리·백업만 수행
- 테스트 시작 전 S10의 IP와 Opal의 station 목록 기록

## 단계별 검증

### A. 연결 전 안정 상태

- Opal SSID와 STA 연결
- S10 `192.168.8.165` ping 및 ARP 상태
- D810 USB 인식
- 서비스 PID가 각각 하나인지 확인
- 앱이 Opal HTTP와 WebSocket에 연결되었는지 확인

### B. 실제 앱 기능

S10 화면에서 사람이 직접 다음 순서로 수행한다.

1. Ready 상태 확인
2. 라이브뷰 시작
3. 첫 프레임 확인
4. AF
5. UI 셔터
6. 촬영 프리뷰와 원본 확인
7. 연사 3회
8. 라이브뷰 종료

각 단계에서 관측기는 시각, S10 연결, WebSocket 연결, Opal 상태, 배터리 관측값, frame failure, 생성 파일과 outbox 상태를 기록한다.

### C. 서비스 복구 시나리오

S10 앱을 종료하지 않고 Opal의 관련 서비스만 재시작한다. SSID 자체는 끊지 않는다. 이때 확인할 것은 “Wi-Fi는 계속 붙어 있고 기존 앱 WebSocket만 끊겼다가 앱이 재연결되는가”이다.

1. bridge 재시작
2. WebSocket 재시작
3. ddserver 재시작
4. 전체 서비스 직렬 재기동
5. USB authorization cycle

각 시나리오 후 S10 앱에서 새로고침 없이 상태가 Ready로 돌아오는지, 라이브뷰와 UI 셔터가 다시 되는지 확인한다.

## 연결이 끊기는 범위

기존 자동 루프에서 회차마다 끊는 것은 Opal 서비스와 카메라 USB 경로다. Opal AP와 S10의 SSID 연결은 끊지 않는다. 따라서 이 테스트는 S10 Wi-Fi 재연결 시험이 아니라, “같은 네트워크에서 서버가 재기동될 때 실제 앱이 복구되는가”를 시험한다.

S10 절전으로 Wi-Fi가 끊기면 별도의 `s10_sleep_or_wifi_loss` 사건으로 기록하고, 카메라 서비스 실패와 섞지 않는다.

## 자동화 경계

현재 PC에는 ADB가 없고, S10에 원격 터치 명령을 보낼 앱 테스트 API도 확인되지 않았다. 그러므로 이번 1차 출사형 검증은 S10 앱 조작을 사람이 수행하고, Opal 관측·타임라인·백업을 자동화한다. 실제 S10 터치까지 자동화하려면 ADB over Wi-Fi 또는 앱 전용 테스트 명령을 별도로 마련해야 한다.

현재는 S10 무선 ADB `192.168.8.165:38917`이 연결되어 있으므로, 실제 버튼 좌표를 사용하는 자동 조작 스크립트도 준비되어 있다. `deploy/scripts/s10-field-ui-test.ps1`은 앱 전면 확인 후 `LIVE start → AF → SHOT → 대기 → STOP live`를 수행하고 화면 캡처와 단계별 JSONL을 로컬에 남긴다. 기존 가상 클라이언트와 달리 이 경로는 실제 S10 앱 화면을 통해 명령을 만든다.

## 합격 기준

- S10 화면 자동 꺼짐 없이 전체 시나리오 완료
- 서비스 복구 후 앱 WebSocket 재연결
- 라이브뷰 첫 프레임, AF, UI 셔터, 프리뷰, 원본 모두 성공
- S10 SSID 연결 손실과 카메라 서비스 실패가 명확히 분리됨
- 로그·타이밍·스크린샷/수동 체크 결과가 PC로 자동 회수됨
- Opal outbox가 전송 후 비워짐
- 테스트 후 Opal 저장공간 5MB 이상 유지

## 현재 테스터와의 차이

기존 20회 루프는 Opal 내부 가상 클라이언트가 기능을 호출한다. 출사형 테스트는 실제 S10 앱이 명령을 만들고, Opal은 그 결과와 복구 과정을 관찰한다. 따라서 기존 루프의 PASS와 이번 테스트의 PASS는 서로 다른 의미로 기록해야 한다.
