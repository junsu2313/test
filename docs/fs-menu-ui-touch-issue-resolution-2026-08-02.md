# F.S 메뉴 UI 터치 문제 해결 기록

- 작성일: 2026-08-02
- 대상: Underlab Camera Flutter 앱 가로 UI
- 기기: Samsung Galaxy S10
- 범위: `MENU`의 F.S(필름 시뮬레이션) 프리셋 UI

## 1. 작업 목적

F.S 메뉴 안에 다음 다섯 개의 촬영 프리셋을 작은 사각형 아이콘으로 제공하고, F.S를 연 뒤에도 다른 메뉴 분류로 정상 이동할 수 있게 만드는 것이 목적이었다.

- 풍경
- 꽃
- 인물
- 움직이는 물체
- 정물

## 2. 발생한 문제

F.S 버튼을 누르면 이후 다른 카테고리 버튼의 터치가 제대로 동작하지 않았다. 다른 메뉴는 정상인데 F.S를 선택한 뒤에만 문제가 재현되어 처음에는 F.S 버튼 자체의 제스처 처리 문제처럼 보였다.

주요 증상은 다음과 같았다.

1. F.S 선택 후 프리셋 아이콘이 보이지 않았다.
2. F.S 선택 후 다른 카테고리로 이동할 수 없었다.
3. 화면에는 F.S가 선택된 것으로 보이지만 오른쪽 설정 영역은 비어 있었다.
4. Flutter assertion이나 앱 크래시는 발생하지 않았다.

## 3. 초기 접근과 한계

초기에는 터치 이벤트 경쟁을 원인으로 보고 다음 변경을 순차적으로 적용했다.

- 메뉴 배경과 메뉴 패널의 히트테스트 레이어 분리
- `Listener.onPointerDown`과 `InkWell.onTap`의 이중 처리 제거
- 카테고리 버튼에 독립적인 불투명 히트영역 적용
- 다섯 버튼을 하나의 고정 터치 레일로 통합
- 선택 시점을 `pointerUp`에서 `pointerDown`으로 변경

이 변경들은 터치 구조를 단순하게 만들었지만 문제를 완전히 해결하지 못했다. 화면에서 보이는 증상만으로는 입력이 끊긴 것인지, 상태 전환이 실패한 것인지, 패널이 잘못 배치된 것인지 구분할 수 없었기 때문이다.

ADB 원격 탭도 실제 손가락 입력과 다르게 동작해 실기 검증 수단으로 사용할 수 없었고, Flutter 위젯 테스트 러너도 해당 환경에서 시작 단계에 멈춰 로그 계측이 필요했다.

## 4. 계측으로 확인한 사실

메뉴 배경, 메뉴 패널, 카테고리 레일에 `MENU_TOUCH` 로그를 추가한 뒤 실기에서 다음 순서로 터치했다.

```text
D → C → A → B → F.S
```

로그에는 모든 입력이 정상적으로 기록되었다.

```text
[MENU_TOUCH] select key=D value=D
[MENU_TOUCH] select key=C value=C
[MENU_TOUCH] select key=A value=A
[MENU_TOUCH] select key=B value=B
[MENU_TOUCH] select key=F.S value=FILM SIM
```

이 결과로 다음 사실을 확정할 수 있었다.

- F.S 버튼은 실제로 터치를 받고 있었다.
- `_category`는 `FILM SIM`으로 정상 변경됐다.
- Flutter 예외나 assertion은 없었다.
- 문제는 버튼 선택 이전이 아니라 F.S 패널이 만들어진 이후에 발생했다.

화면 캡처에서도 F.S 버튼은 흰색 선택 상태였지만 오른쪽 프리셋 패널은 빈 영역으로 나타났다.

## 5. 실제 원인

일반 메뉴의 설정 패널은 `SizedBox(width: 122)` 안에 배치되어 있었지만, F.S 전용 `_FilmPresetSettingGroup`만 고정 폭 컨테이너 없이 `Row`에 직접 들어가 있었다.

그 결과 F.S 패널이 생성될 때 느슨한 가로 제약 아래에서 패널의 표시 폭과 히트테스트 영역이 서로 다르게 계산되었다. 화면에는 내용이 보이지 않았고, 잘못 계산된 영역이 카테고리 레일 쪽 입력에도 영향을 주었다.

즉 문제의 본질은 다음과 같다.

```text
F.S 터치 실패가 아님
→ F.S 상태 전환은 성공
→ F.S 전용 패널의 레이아웃 제약 실패
→ 빈 패널과 잘못된 히트영역 생성
→ 이후 메뉴 터치가 고장 난 것처럼 보임
```

## 6. 해결 방법

### 6.1 F.S 패널 폭 고정

F.S 전용 패널도 다른 설정 패널과 동일하게 `122dp` 고정 폭 안에 배치했다.

```dart
SizedBox(
  width: 122,
  child: _FilmPresetSettingGroup(...),
)
```

### 6.2 메뉴를 고정 좌표 구조로 변경

카테고리 레일과 설정 패널을 `Row`의 자동 배치에 맡기지 않고 `Stack` 안의 고정 좌표로 분리했다.

```text
x=0    : 카테고리 레일, 폭 24dp
x=30   : 구분선
x=36   : 설정 패널, 폭 122dp
전체 폭: 158dp
```

이 구조에서는 F.S 패널의 내용이나 높이가 변해도 카테고리 레일의 위치와 터치 영역이 변하지 않는다.

### 6.3 카테고리 입력 경로 단순화

다섯 개 버튼의 개별 제스처 경쟁을 제거하고 하나의 고정 레일에서 터치 위치를 카테고리 인덱스로 변환하도록 했다.

```dart
final index = (event.localPosition.dy / 27).floor();
```

선택은 `pointerDown`에서 즉시 수행하므로 손가락을 이동하거나 위젯이 갱신되면서 `pointerUp`이 유실되는 경우도 피했다.

## 7. 검증 기준

수정 APK는 빌드 후 S10에 직접 배포했다. 최종 실기 검증은 다음 순서로 수행한다.

1. `MENU`를 연다.
2. F.S를 선택한다.
3. 오른쪽에 `프리셋`과 다섯 개 아이콘이 표시되는지 확인한다.
4. 풍경, 꽃, 인물, 움직이는 물체, 정물 아이콘을 각각 선택한다.
5. F.S 선택 후 D, C, A, B 카테고리로 즉시 이동되는지 확인한다.
6. 메뉴 여백과 X 버튼의 동작을 확인한다.
7. 로그에 Flutter assertion이나 `RenderFlex overflow`가 없는지 확인한다.

## 8. 재발 방지 원칙

- 같은 영역에 들어가는 메뉴 패널은 동일한 폭 제약을 사용한다.
- 보이는 영역과 히트테스트 영역이 일치하도록 고정 좌표를 사용한다.
- 특정 메뉴만 별도의 레이아웃 규칙을 갖지 않게 한다.
- 터치 문제는 버튼 콜백, 상태 전환, 레이아웃 생성의 세 단계로 나눠 계측한다.
- 화면상 선택 표시만으로 기능 성공을 판단하지 않는다.
- UI 변경은 빌드뿐 아니라 실제 기기에서 전환 전후 터치까지 검증한다.

## 9. 결론

이 문제는 F.S 버튼의 터치 실패가 아니라 F.S 전용 패널의 폭 제약 누락으로 발생한 레이아웃·히트테스트 결함이었다. 로그 계측을 통해 입력과 상태 전환이 정상임을 먼저 증명한 뒤, 패널의 배치 구조를 고정 폭·고정 좌표 방식으로 변경해 원인을 제거했다.

이번 작업의 핵심 교훈은 **터치가 안 되는 것처럼 보이는 UI 문제도 실제 원인은 터치 처리보다 상태 전환 이후 생성되는 레이아웃에 있을 수 있다**는 점이다.
