# 라이브뷰 60fps 접근 실측 — 2026-07-29

## 기준선

- 5차 동결: UI 평균 `55.94 fps`, p95 `58.1 fps`, 최대 `58.5 fps`
- 당일 20초 재측정: 평균 `56.33 fps`, 최소 `52.2`, 최대 `58.3 fps`
- 전체 지연: 주로 `14 ms`

## 채택한 변경

브리지와 WebSocket 소켓 쓰기 루프가 첫 전송부터 `data:sub(1)`을 호출해
약 33KB JPEG 전체를 매 프레임 복사하고 있었다. 첫 쓰기에는 원본 Lua
문자열을 직접 전달하고, 실제 부분 쓰기가 발생한 경우에만 나머지 문자열을
잘라내도록 변경했다.

### 측정 결과

- UI 30초 평균: `57.03 fps`
- p10 / p50 / p95 / 최대: `54.0 / 57.2 / 59.2 / 59.5 fps`
- 전체 지연: `14~15 ms`
- 브리지 stream send 평균: 약 `2.71 → 2.01 ms` (`-25.7%`)
- request gap 중앙값: 약 `3.97 → 2.94 ms` (`-25.9%`, 약 `-1.03 ms`)

현재 배포에는 이 JPEG 복사 제거를 유지했다.

## 배터리 교체 후 최종 60초 검증

배터리 `100%` 상태에서 배포된 브라우저 UI와 별도 Opal 시스템 샘플러를
동시에 사용해 다시 측정했다.

| 지표 | 5차 동결 | 복사 제거 최종 | 변화 |
| --- | ---: | ---: | ---: |
| UI FPS 평균 | 55.94 | 57.09 | `+2.1%` |
| UI FPS p10 / p50 / p95 | 52.7 / 56.5 / 58.1 | 53.7 / 57.6 / 59.8 | 전 구간 개선 |
| UI 최대 표본 | 58.5 | 60.8 | 측정 창 오차를 포함한 순간 표본 |
| 실생산 FPS | 55.72 | 56.40 | `+1.2%` |
| 전체 지연 평균 | 14.22 ms | 14.28 ms | 유지 |
| 전체 지연 p50 / p95 / 최대 | 14 / 15 / 15 ms | 14 / 15 / 15 ms | 동일 |
| 시스템 CPU busy | 39.44% | 40.73% | `+1.29 pp` |
| Bridge+WS CPU / FPS | 0.406 | 0.390 | 프레임당 약 `-3.9%` |

UI 최대 `60.8 fps`는 1초 이동 창과 브라우저 시계 오차가 포함되므로
카메라가 60 fps를 초과 생산했다는 근거로 사용하지 않는다. 지속 성능의
대표값은 UI 평균 `57.09 fps`, 실생산 `56.40 fps`, UI p95 `59.8 fps`다.

## 폐기한 후보

1. 메타데이터와 JPEG를 하나의 WebSocket 메시지로 결합
   - 평균 `56.33 → 55.53 fps`, 최소 `52.2 → 50.7 fps`
   - 브라우저 Blob 재분리 비용 때문에 회귀하여 원복
2. 내부 스트림의 고정 64바이트 prefix를 한 번에 읽기
   - 순간 `59.8 fps`, 평균 `56.94 fps`
   - 복사 제거 단독 평균 `57.03 fps`보다 개선되지 않아 원복
3. 활성 내부 클라이언트에서 stream accept 생략과 메트릭 테이블 재사용
   - 화면에 `59.3 fps`가 고정됐지만 frame ID가 멈춘 착시
   - 재연결 경로 회귀와 frame failure 증가를 확인하고 즉시 원복

## 최종 상태

- LIVE off
- 카메라 Ready
- frame failure `0`
- 배터리 `100%`

JPEG 복사 제거는 최종 배포 상태로 유지한다. 이후 비교 기준은 UI 평균
`57.09 fps`, 실생산 `56.40 fps`, 지연 p50 / p95 `14 / 15 ms`로 사용한다.
