# 라이브뷰 중심 카메라 스케줄러 원칙 · 2026-07-30

## 문서 목적

이 문서는 liveView를 단순한 구도 확인 기능이 아니라, 현재 카메라 설정을
반영하는 상시 전자식 뷰파인더로 운영하기 위한 기본 스케줄링 원칙을 정의한다.

목표는 라이브뷰를 가능한 한 계속 유지하면서 설정 읽기·변경, AF, 촬영 명령을
안전하게 처리하고, 사용자가 명령 실행 상태를 예측할 수 있게 하는 것이다.

## 기본 전제

- liveView는 카메라 연결 후 항상 동작하는 기본 상태다.
- 카메라에 접근하는 PTP 생산자는 하나뿐이다.
- 프레임을 모두 보존하는 것보다 최신 프레임을 빠르게 보여주는 것이 중요하다.
- 설정 변경은 UI 값만 바꾸는 작업이 아니라 카메라와 liveView 상태를 바꾸는 작업이다.
- 59.94fps는 목표값이며, 실제 지속 성능은 스케줄러 적용 후 다시 측정한다.

## 12개 스케줄링 원칙

### 1. 라이브뷰는 항상 켜둔다

라이브뷰를 필요할 때만 시작하는 기능으로 취급하지 않는다. 카메라 연결 후
하나의 장기 실행 프레임 생산자가 계속 동작하며, 모든 명령은 이 상태를
기준으로 처리한다.

### 2. 카메라 명령 통로는 하나만 둔다

프레임 생산, 설정 읽기·변경, AF, 촬영이 서로 다른 PTP 생산자가 되면 카메라
락과 세션이 충돌한다. 모든 카메라 접근은 단일 arbiter 또는 단일 큐를 거친다.

### 3. 프레임 하나가 끝난 뒤 명령 큐를 확인한다

카메라 명령을 프레임 생산 중간에 강제로 끼워 넣지 않는다. 프레임 단위의
안전한 경계에서 큐를 확인하고, 다음 프레임 전에 처리할 명령을 선택한다.

### 4. 설정 읽기는 가장 급하지 않게 처리한다

설정 읽기는 화면 상태를 최신화하지만 촬영 명령은 아니다. 프레임 처리와 AF·
SHOT을 방해하지 않도록 낮은 우선순위로 실행하고, 필요한 순간에만 요청한다.

### 5. 빠르게 바뀐 설정은 마지막 값만 적용한다

사용자가 다이얼을 빠르게 여러 번 움직이면 중간 값까지 카메라에 모두 보낼
필요가 없다. 같은 설정 항목의 대기 요청은 합치고 가장 최근 값을 적용한다.

### 6. AF와 SHOT은 설정 읽기보다 우선한다

AF와 촬영은 사용자의 직접적인 촬영 의도다. 대기 중인 상태 읽기보다 우선하되,
이미 실행 중인 안전한 카메라 명령을 중간에 강제 종료하지는 않는다.

### 7. 촬영 중에는 다른 설정 명령을 기다리게 한다

셔터 동작과 이미지 기록이 진행되는 동안 설정을 바꾸면 카메라 상태가
불명확해질 수 있다. 촬영 시작부터 완료 확인까지 다른 설정 명령을 보류한다.

### 8. 설정 변경 중에는 마지막 프레임을 유지한다

설정 적용 때문에 새 프레임이 잠시 늦어져도 화면을 검게 만들거나 빈 상태로
바꾸지 않는다. 사용자는 마지막 유효 프레임을 계속 보며 작업 상태를 확인한다.

### 9. 적용 완료 후 새 설정값을 프레임과 함께 반영한다

UI를 먼저 바꿔 실제 카메라와 어긋나게 만들지 않는다. 카메라가 적용을
확인하면 committed 값을 갱신하고, 그 설정이 반영된 프레임과 함께 표시한다.

### 10. 오래 걸리는 명령은 프레임을 쌓지 않는다

명령이 오래 걸릴 때 프레임을 버퍼에 계속 쌓으면 화면 지연이 누적된다. 오래된
프레임은 폐기하고, 명령 완료 후 도착하는 최신 프레임부터 표시한다.

### 11. UI는 적용 상태를 즉시 보여준다

설정 버튼을 누른 순간 `적용 중` 상태를 표시하고, 카메라 확인이 끝나면
`적용 완료` 또는 오류 상태로 바꾼다. 화면과 카메라 상태가 다를 때는 이를
명확히 표시해 사용자가 추측하지 않도록 한다.

### 12. 설정을 매 프레임마다 읽지 않는다

모든 프레임마다 카메라 설정을 다시 읽으면 프레임 생산률과 USB 여유를
소모한다. 설정 변경 직후, 연결 복구 직후, 또는 제한된 주기의 상태 확인에서만
읽고, 평상시에는 마지막으로 확인된 값을 사용한다.

## 사용자 경험 기준

- 화면은 가능한 한 계속 최신 프레임을 보여준다.
- 설정 변경 중에도 화면이 멈추거나 검게 변하지 않는다.
- 사용자의 마지막 선택이 최종적으로 적용된다.
- 촬영 명령은 설정 읽기보다 먼저 처리된다.
- 실제 적용 전에는 확정값처럼 표시하지 않는다.
- 프레임 지연과 카메라 명령 실패를 서로 다른 상태로 표시한다.
