# 4차 프레임 최적화 — 2026-07-28

## 결론

- 상태: 실제 Opal에 적용·배포·측정 완료
- 변경: JPEG와 WebSocket 패킷의 프레임별 전체 문자열 복사 제거
- 안전성: LIVE 시작·정지·재시작 정상, 최종 상태 LIVE off / 배터리 100%
- 비용 절감: WebSocket CPU `4.64% → 4.62%`로 약 `0.5%` 감소
- 체감 지표: 전체 지연 p50 `28 ms` 유지, p95 `32 → 31 ms`
- 판단: 성능 저하 없이 불필요한 메모리 복사를 제거했지만 CPU 절감 폭은 작다.

## 변경 내용

기존에는 브리지가 메타데이터와 JPEG를 하나의 큰 Lua 문자열로 결합했고,
WebSocket 서버가 이를 다시 잘라낸 뒤 프레임 전체를 WebSocket 패킷 문자열로
재조립했다. 4차 버전은 다음처럼 작은 헤더와 JPEG 원본을 따로 전송한다.

1. 브리지: 패킷 헤더·메타데이터 prefix와 JPEG frame을 별도 `write`
2. WebSocket: 프레임 헤더와 JPEG payload를 별도 `write`
3. 직접 스트림 메타데이터: JSON decode/re-encode 없이 원문 전달
4. 기존 저빈도 파일 캐시 fallback은 그대로 유지

## 측정 조건

- 장비: GL.iNet Opal과 Nikon D810
- 연결: 로컬 LAN `192.168.8.1`만 사용
- Tailscale SSH 및 외부 노출 없음
- Opal 샘플러: 60초, 10 ms 간격
- 브라우저: `e2e=total`, 1초 간격 50개 표본
- 전체 지연: D810 `0x9203` 요청 시작부터 브라우저 이미지 `load`까지
- 비교 기준: 배포된 3차 직접 스트림 측정값

프레임 생성률은 카메라 노출과 장면에 따라 달라질 수 있으므로 `+6.20%` 전체를
복사 제거의 효과로 해석하지 않는다. CPU 결과 역시 시스템 전체는 오히려
`0.27 pp` 높아 측정 변동 범위이며, 확실히 확인된 직접 비용 감소는 WebSocket
프로세스의 약 `0.5%`뿐이다.
