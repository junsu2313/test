# 0728 스케줄러 중심 모듈형 설계 방향

작성일: 2026-07-28

## 1. 기본 방향

이 프로그램의 핵심은 단순한 카메라 리모컨이 아니라 예약 촬영을 안정적으로 수행하는 스케줄러다. 앞으로 설계하는 모든 기능은 스케줄 촬영의 정확성, 지속성, 복구 가능성을 우선 기준으로 판단한다.

## 2. PTP 통신 원칙

D810과의 PTP 세션은 사실상 한 번에 하나의 명령만 처리할 수 있다. 따라서 라이브뷰, 설정 변경, 상태 조회, 촬영 명령을 병렬로 실행하지 않고 중앙 명령 큐에서 직렬화한다.

권장 우선순위는 다음과 같다.

1. 예약 촬영 명령
2. 촬영 전 설정 적용
3. 수동 조작
4. 라이브뷰 프레임 갱신
5. 상태 및 노출 정보 조회

라이브뷰와 노출 정보는 완전한 병렬 처리가 아니라 프레임 수신과 상태 조회를 교차 실행하는 방식으로 동작시킨다. 이때 과도한 폴링, 큰 JPEG 반복 전송, 무제한 재시도는 피한다.

## 3. 모듈 구성

기능 간 의존성을 줄이기 위해 다음 모듈을 독립적으로 구성한다.

- Scheduler: 예약 시각, 작업 순서, 우선순위 관리
- PTP Queue: 카메라 명령 직렬화, 실행 상태, 타임아웃 관리
- Preset: 카메라 설정값의 저장·비교·적용 요청
- Capture: 셔터 실행, 촬영 결과 확인, 미리보기 갱신 요청
- Live View: 프레임 수신과 화면 표시
- Status: 카메라·세션·배터리·설정 상태 조회
- Recovery: 실패, 연결 끊김, 세션 복구 처리
- Settings UI: 설정 입력, 임시값 표시, 적용·취소 처리

UI 모듈은 카메라 통신을 직접 수행하지 않고 PTP Queue 또는 모듈 인터페이스를 통해 요청한다. Scheduler 역시 UI를 직접 제어하지 않고 작업 결과 이벤트를 발행한다.

## 4. 설정 UI 방향

오팔 리모컨의 제한된 화면을 고려해 설정 UI는 전체 화면의 2번째 레이어로 표시한다. 기존 라이브뷰와 컨트롤 화면은 반투명 배경 뒤에 유지하고, 설정 화면은 그 위에서 동작한다.

설정은 우선 핵심 항목만 제공한다.

- 노출: 조리개, 셔터속도, ISO
- 초점: AF 모드, 초점 영역
- 촬영: 화이트밸런스, 화질, 이미지 크기
- 기타: 측광, 드라이브 모드

사용자가 값을 변경하면 먼저 임시값으로 보관한다. `적용`을 눌렀을 때 변경된 항목만 PTP Queue에 등록하고, 성공·실패 항목을 각각 표시한다. 프리셋 저장도 적용 결과와 분리한다.

## 5. 스케줄러와 설정의 관계

예약 촬영 직전에는 필요한 프리셋을 먼저 적용하고, 적용 결과가 확인된 뒤 촬영 명령을 실행한다. 설정 적용 중에는 같은 카메라에 대한 중복 명령을 허용하지 않는다.

스케줄 작업은 UI가 닫혀 있거나 설정 레이어가 열린 상태에서도 계속 유지되어야 한다. 사용자가 수동 조작을 시도하면 현재 예약 작업과의 충돌 여부를 확인하고, 필요한 경우 대기·거부·예약 취소 중 하나를 명확히 표시한다.

## 6. 구현 순서

1. PTP Queue 인터페이스와 작업 상태 모델 정의
2. Scheduler의 예약 작업 모델 정의
3. 촬영 전 프리셋 적용 흐름 구현
4. 설정 UI 레이어 구현
5. 촬영 결과·실패·복구 이벤트 연결
6. 라이브뷰와 상태 조회를 큐에 연결

브릿지의 책임과 기존 동작은 유지하며, 새 기능은 기존 브릿지를 직접 수정하기보다 명확한 모듈 인터페이스를 통해 연결한다.
