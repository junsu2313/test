# 촬영 파이프라인 지연시간 기준선 — 2026-08-06

실제 Nikon D810/Opal/S10 무선 연결 상태에서 새로 촬영해 측정한 기준선이다.

| 구간 | 측정값 |
|---|---:|
| 셔터 요청 응답 | 1.543초 |
| 촬영 후 썸네일 프리뷰 수신 | 0.273초 |
| 촬영 후 썸네일까지 순차 합계 | 약 1.816초 |
| 9MP 원본 수신 | 3.702초 |
| 촬영 후 원본까지 순차 합계 | 약 5.245초 |
| 썸네일 파일 크기 | 9,037 bytes |
| 원본 파일 크기 | 8,517,539 bytes (약 8.52MB) |

측정 조건:

- `action-v21?action=shutter` 실행 후 `captured-preview?t=1`, `captured-object?t=1` 순서로 요청
- 라이브뷰 유지 상태에서 측정했으며, 원본 수신 경로의 라이브뷰 stop/start 동작은 현재 구현을 유지
- 기준선은 앱 UI 애니메이션 시간과 Android 디코딩 시간은 제외한 네트워크/CGI 응답 시간

다음 최적화의 성공 기준은 원본 화질과 저장 동작을 유지하면서 썸네일 표시 지연과 원본 전환 지연을 이 기준선보다 줄이는 것이다.

## 1차 전송 최적화 결과

- PTP 청크 크기: 2MiB → 4MiB
- 라이브뷰 stop 후 안정화 대기: 250ms → 150ms
- 원본 수신 재측정: 3.450초, 반복 측정 3.522초
- 기존 3.702초 대비 약 0.18~0.25초(약 5~7%) 개선
- 이번 촬영 원본은 8,380,106 bytes(약 8.38MB)로 기존 기준 이미지보다 작으므로, 개선폭은 동일 파일 크기 재측정에서 최종 확정한다.

## 전반 파이프라인 최적화

- Flutter 썸네일 요청을 촬영 응답 직후 시작하고, 0/100/180/300/480/700ms 간격으로 저장 완료까지 재시도하도록 변경했다.
- 9MP 원본은 썸네일을 유지한 상태에서 먼저 디코딩·캐시한 뒤 화면에 교체하여 전환 프레임의 버벅임을 줄였다.
- 실제 3회 촬영에서 셔터 응답은 1.565~1.583초(평균 약 1.577초), 썸네일 준비는 셔터 응답 후 1.628~2.015초였다.
- 셔터 내부 고정 대기와 준비 폴링 간격을 줄이는 실험은 기존 1.543초보다 개선되지 않아 원래 안전값으로 되돌렸다. 이 구간은 D810 내부 처리 시간이 지배한다.
- 8,484,693-byte 원본 반복 수신은 3.517초와 3.945초로 무선 변동폭이 확인됐다. 4MiB 청크와 150ms 라이브뷰 안정화 설정은 유지한다.
- Flutter 정적 분석, 촬영/라이브뷰 계약 검사, release APK 빌드, S10 무선 업데이트 설치와 실행 검증을 통과했다.
